An **aggregate** is a consistency boundary: one thing whose rules can be checked without looking at anything else, such as a user. It is rebuilt from its own **stream** of events, and it changes only by raising new ones.

Why events rather than rows? Because the history is the data. You can answer "when did this user change their email, and why?" from the stream, build a new read model from old events, and test a rule by saying what happened before and what should happen next.

## Rules for a permanent log

Stored events are kept forever. The rules in `internal/platform/es/AGENTS.md` follow from that:

- Events are immutable facts. To fix data, append a correcting event; never edit or delete a stored one.
- A registered name never changes, and neither does the shape stored under it. A new shape gets `.v2` and an upcast from `.v1`.
- Events hold no secrets: no tokens, passwords or codes. They hold no personal data beyond what the fact needs, and `Meta` holds identifiers only.
- `Apply` only assigns. Validation happens before `Raise`.
- Decoding an event type that isn't registered returns `es.ErrUnknownEventType`, never a panic.
