Tests are written against behaviour you can name: "a stale version conflicts", "a code works once", "another user gets a 404". Each layer has its own kind of test, and the fast ones need no Docker.

## Commands

| Command | Runs |
|---|---|
| `go test -short ./...` | Everything except tests that start containers. No Docker needed. |
| `make test` | `go test -race -shuffle=on ./...`: everything, in random order, with the race detector, including the MySQL and MongoDB containers. |
| `make check` | What CI runs, except the container and end-to-end tests: formatting, `go fix`, vet and staticcheck for every store build and the end-to-end tests, the short tests with the race detector, the proto lint and generated-file check, the web app's checks and the Helm chart's. |
| `make e2e` | The end-to-end suite, against a stack started with `make up`. |
| `make e2e-web` | The Playwright suite, against the same stack. |

CI runs the short tests once per store build (memory, `persistence_mysql` and `persistence_mongodb`), and the container tests in a job per database.

## HTTP: the authorization matrix

Each service has a table-driven test, `TestAuthorizationMatrix`, that calls every route as each kind of caller and checks the status each gets: anonymous, the owner, another user, a token without the route's scope, and an OAuth app's own client-credentials token. auth also calls its routes with a third-party app's token for a user, which may not manage sessions or apps. A route with no row fails the test: in user, through `TestEveryRouteHasARow`. This is the test that would have caught the 2022 layout's account-takeover bug.

`TestOpenAPIDocumentsEveryRoute` checks the router against `api/<service>.openapi.yaml`: every route is documented and every documented route exists. The tests' HTTP rig also checks every response against its schema in that document.

## End to end

`make e2e`, which runs `go test -tags e2e ./e2e/...`, drives the running stack through the gateway. CI runs it against the memory, MySQL and MongoDB builds, each started with `make up STORE=<store>`.

Playwright drives the web app on the memory build: it signs in through the Mailpit API, creates an OAuth app, runs the client-credentials flow and revokes a session.
