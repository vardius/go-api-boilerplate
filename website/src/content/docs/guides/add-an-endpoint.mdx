Every public route has four parts that change together: the handler, its OpenAPI entry, its row in the authorization matrix, and the web app's schema for its response. Tests fail when any one of them is missing, which is the point: a route nobody thought about authorizing is how the 2022 layout got its worst bugs.

<Steps>

1. **Pick the route.** Name the resource, not the action: `POST /v1/me/email-change`, not `/v1/changeEmail`. A route under `/v1/me` acts on the caller, which keeps IDs of other users out of URLs.

2. **Write the handler** with `httpx.Handle`. It returns an error instead of writing one, so every failure goes through the one error table and becomes a problem response:
   - decode the body with `httpx.DecodeJSON[T](r, maxBytes)`, which rejects unknown fields, trailing data and oversized bodies;
   - take the caller from `authn.FromContext(r.Context())`, never from the body or the path;
   - call the use case, and write the result with `httpx.WriteJSON`.

3. **Protect it.** Wrap the route in the narrowest guard that fits:
   - `authn.Require(scopes...)`: any valid token with these scopes;
   - `authn.RequireUser(scopes...)`: a user's token, not a client's;
   - `authn.RequireFirstParty()`: only the web app's own session.

   A route with none of these is public. Rate-limit a public route that sends email or creates anything.

4. **Register it** on the service's gorouter v5 router. Handlers read path parameters with the standard `r.PathValue`.

5. **Document it** in `api/<service>.openapi.yaml` (OpenAPI 3.1): request body, every response status, and the problem response for errors. The contract test fails if a route is missing from the file, if the file lists a route that doesn't exist, or if a response doesn't match its schema.

6. **Add its authorization-matrix row.** The matrix is a table-driven test: every route, called as anonymous, another user, the owner, and a token with the wrong scope, with the status each must get. It fails when a route has no row.

7. **Update the web app** if it calls the route: the zod schema that validates the response lives in `web/`, and must match the OpenAPI schema.

8. **Run the checks:**

   ```sh
   go test -race ./internal/user/httpapi/...
   make check
   ```

</Steps>

## Cookies and cross-site requests

Browser requests carry the `access_token` cookie, so an unsafe method (`POST`, `PATCH`, `DELETE`) on a cookie-authenticated route is protected by `http.CrossOriginProtection`. A cross-site form post gets a `403` problem. You don't need CSRF tokens: the gateway puts the app and the APIs on one origin.
