Tests are written against behaviour you can name: "a stale version conflicts", "a code works once", "another user gets a 404". Each layer has its own kind of test, and the fast ones need no Docker.

## Commands

| Command | Runs |
|---|---|
| `go test -short ./...` | Everything except tests that start containers. No Docker needed. |
| `go test -race -shuffle=on ./...` | Everything, in random order, with the race detector. This is what CI runs. |
| `go test -race -tags persistence_mysql ./...` | The same with the MySQL build. CI runs the memory, MySQL and MongoDB builds. |
| `make check` | Formatting, vet, lint, tests and the generated-code check: all of CI. |
| `make e2e` | The end-to-end suite against `docker compose up`. |

## HTTP: the authorization matrix

Each service has a table-driven test that calls every route as anonymous, another user, the owner, and a token with the wrong scope, and checks the status each gets. A route with no row fails the test. This is the test that would have caught the 2022 layout's account-takeover bug.

A second test checks the router against `api/<service>.openapi.yaml`: every route is documented, every documented route exists, and every response matches its schema.

## End to end

`go test -tags e2e ./e2e/...` drives the running stack over HTTP. CI runs it against the memory, MySQL and MongoDB builds, each started with `docker compose up --wait`.

Playwright drives the web app on the memory build: it signs in through the Mailpit API, creates an OAuth app, runs the client-credentials flow and revokes a session.
